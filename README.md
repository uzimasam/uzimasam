## What's Here

This profile is a public snapshot of the engineering work I can share: product context, selected public systems, technical artifacts, and notes from the systems I build.

Most of my commercial work lives in private company repositories. The public thread here is how I approach product engineering: model the real workflow, protect important state, make failures recoverable, and own the result in production.

## Operating Philosophy

I think in workflows, system state, and production outcomes, not isolated tickets.

Good software should make hard things feel usable. Payment providers, financial processing, queues, integrations, and infrastructure can be complicated internally; the product should still feel clear and dependable.

For systems handling money, correctness is a product feature. I design around explicit invariants, recoverable failures, reconciliation, and visibility into what actually happened.

Outside software, I work in live sound. It reinforces the same instinct: absorb complexity behind the scenes so the audience experiences something seamless.
